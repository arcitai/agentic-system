# Backlog direction for 0.2.0

Revision: 0.2.0 · Updated: 2026-11-13

A recommendation for each open issue under the 0.2.0 direction. The issues stay the
record: this page changes no issue, hold, grant or installation, and it does not
replace their evidence. The owner has authorized this transition; each action still needs its applicable proof and scope.

## Direction in one paragraph

Agentic System is the prepared ground and its boundaries: agent environment, project
foundation, and operations and maintenance. One project agent carries an accepted
task end to end on the model the owner chooses, and calls helpers or reviewers when
useful. There is no prescribed internal AgentOps role. Entry is an optional method
for an assistant outside a project. Evaluate is used when a comparison could change
a decision. Defence is an optional domain method. The software stage methods leave
the active distribution; a project selects native, project or packaged methods
instead. How much review a result gets is each project's choice.

## Where 0.2.0 stands (13 November 2026)

Three states are kept apart throughout: **source** (text exists in the authoring
edition or repository), **installed** (the bytes are present and discovered in a
named tool) and **native acceptance** (observed working in the actual installation).

- Source: the authoring edition of the guide, its subpages and three shared skills
  carries 0.2.0. Six retired skill pages remain with history banners. The repository
  is on an in-progress source branch.
- Not done: no pull request, merge, release or installed skill adoption.
- Unchanged: the Lab's two-review default, its holds (general intake, environment
  retirement, #114 delivery), its grants and its network scopes. Schedules are
  disabled and no new schedule is selected.
- Lab host, dated observation: after a host restart the existing Lab service was
  started by the operator on Stable 0.1.6, with no active runs and a verified idle
  recovery copy. The latest stable release is downloaded but not installed. An OS
  update check failed and no system upgrade was made. Detail belongs in #34 and #83.

## Priorities

1. **Deliver 0.2.0 as a reviewed release**, then adopt it per project: #122, #91,
   and the rewording of #3 and #111.
2. **Close the real native gaps.** Documentation does not close them: #34, #83, #32, #80.
3. **Owner decisions:** confirm #30, decide #90, hand #93 to its own project.
4. **Optional experiments**, run only when a decision depends on one: #115, #125,
   #97, #99, #50, #49.
5. **Everything else stays parked** with its existing revisit trigger. Unchanged
   checks are not requalified, and no issue is closed to reach a number.

Recommendations used: *finish*, *rescope*, *park*, *close as not planned*. Nothing
is recommended for closing as completed today, because no 0.2.0 change is released.
