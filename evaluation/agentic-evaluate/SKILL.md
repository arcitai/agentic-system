# Agentic System Evaluate

Use when a comparison could change a decision: one model, method, skill, review setting or configuration against another, in software, BI, defence, research or other work. It is not the review of an everyday task result and not a standing programme. Whichever agent is asked runs it. An evaluator in its own environment is a bounded helper, not a higher permission tier.

Start from the decision and an explicit hypothesis. First check whether existing evidence already settles it; if it does, say so and run nothing. Otherwise use the existing agreed limits, or settle a genuinely missing budget, and use only models, accounts and spend the owner has selected or delegated. Report an unavailable model; do not replace it.

Select representative authorised cases and the evidence needed to tell the alternatives apart. The project's selected methods supply the domain criteria. Fix what must not vary: the project definition and skill revisions where used, input revisions, dependency and environment revisions, task criteria, harness and model versions, tools and relevant settings. Use enough repetitions for the claim. Explain uncertainty instead of inventing a universal sample count or treating one example as a benchmark.

For a model-only comparison, start independent attempts from the same frozen native session checkpoint, or the same retained context package. Keep its input history, definition and skill versions, candidate files or data, tools, permissions and agreed budget; change only the model under test. A transcript alone does not restore task or provider state. Record native lineage and unavoidable context differences; a difference in harness, system or tool context, or state means it is not a model-only comparison, and unavailable exact replay limits the conclusion. Use the existing native fork or a bounded retained package, not a custom replay engine.

Keep attempts from reading each other's outcomes, and preserve their history and artifacts before removing disposable environments. Retain failures, timeouts, review and fix cycles, and attempts discarded during selection. Keep private expected results away from the work under test; nothing being evaluated may modify its own oracle or acceptance criteria. Judge the resulting artifacts and behavior, not the model's rating of itself.

Use objective domain checks where they exist. An optional model judge applies a rubric agreed before the runs; its score is a judgment, not proof of correctness. Several judges need a purpose, a way to handle disagreement and a budget. Missing evidence stays unknown.

Count the whole attempt: the main work, helpers, review, repair, the evaluation itself and human help. Report accepted outcomes, defects and rework, human intervention and time, elapsed time, and available usage or cost. Unknown is null, not zero. Distinguish estimates, subscription windows and actual billed cost. For cost per accepted outcome, divide all attempt costs, including failed attempts, by accepted outcomes. An unknown material component leaves the total unknown: report a lower bound or an inconclusive comparison, not a complete price. Token throughput alone is not value.

Return a report with an adopt, reject, inconclusive or defer recommendation for the specified task and configuration. Disclose confounders, coverage and limits. A synthetic rehearsal establishes only that rehearsal's behavior; live installation and business outcomes need their own observations. Recommend the smallest useful change and its next check.

The evaluation changes no model, skill, account, spend policy or project definition. Adoption and delivery follow existing authority. A proposed method or configuration change goes through the project's normal change route; an experiment need not change product code.
